# Teomoony (터무니)

**단지코드 하나로 건축물대장 · 토지 · 건물 · 실거래가를 전부 조회한다.**

건축물대장을 기준(master)으로 두고, 나머지 축을 PNU 또는 건물관리번호로 연결한다.

> 갱신 2026-10-16 / 적재 범위: **서울 종로구 전체 + 성북구 전체**

## 2. 연계 키 체계

| 축 | 키 | 비고 |
|---|---|---|
| 건축물대장 계층 | `mgmBldrgstPk` / `mgmUpBldrgstPk` | **기본개요에만** 있다 |
| 지번 / 토지 | **PNU 19자리** | 대장이 구성요소 제공 |
| 건물 | **건물관리번호 25자리** | **앞 19자리 = PNU** |
| 실거래가 | PNU (조립) | 유일하게 코드를 안 준다 |
| 건축인허가 | PNU | 코드로 준다. **재개발은 들어오지 않는다**(주택법 대상) |
| K-apt | `bjdCode`(법정동 10) + `kaptAddr` 지번 | **PNU 를 못 믿는다** — 정책.md 3-7 |
| 실거래 단지 구분 | `aptSeq` | 대장 없이 단지를 가르는 유일한 키. `bld_nm` 에 단지명 포함 |
| 도로명 | `naRoadCd`+`naUgrndCd`+`naMainBun`+`naSubBun` | 키만, 상대 데이터 없음 |

### PNU 19자리

```
법정동코드(10) + 대지구분(1) + 본번(4) + 부번(4)
```

> ⚠️ 대장의 `platGbCd` 는 `0=대지 / 1=산 / 2=블록`, PNU 대지구분은 `1=일반 / 2=산`.
> 변환은 `meta.fn_make_pnu()` 안에만 둔다. 파이썬에서 문자열로 조립하지 않는다.

### 건물관리번호 = PNU + 일련번호

```
1111018400 1 0318 0024 000002
└ 법정동10 ┘ 산 └본번┘└부번┘└일련6┘
└──────── 앞 19 = PNU ────────┘
```

이 덕분에 건물 -> 필지 -> 단지가 **문자열 매칭 없이** 떨어진다.
juso 검색 API 로 받으려던 건물관리번호를 VWorld 가 그냥 준다.

### 실거래가만 키가 없다

```
sggCd = 11110   umdNm = '청운동'(이름)   jibun = '56-45'(문자열)

umdNm + sggCd --(meta.lawd_code)--> 법정동코드 10
jibun         --(파싱)-----------> 산여부 / 본번 / 부번
                     ↓  PNU 조립 -> gold.complex_pnu -> 단지
```

**아파트 매매만은 예외.** `AptTradeDev`(상세) 가 `umdCd`/`landCd`/`bonbun`/`bubun`
을 줘서 이름 경유 없이 바로 조립된다(`CODE_DIRECT`). 구 엔드포인트 `AptTrade`
는 코드를 안 주므로 쓰지 않는다.

## 3. 종목별 매칭 가능성 (실거래가)

| 종목 | 지번 | 매칭 |
|---|---|---|
| 아파트 매매 상세 | 코드 제공 | `CODE_DIRECT` |
| 아파트 전월세 / 연립다세대 / 오피스텔 | `56-45` | `LAWD_JIBUN` |
| **단독다가구 매매·전월세** | `1**` 또는 없음 | **`MASKED` 불가** |
| **토지 매매** | `1**` | **`MASKED` 불가** |
| **상업업무용 매매** | `1**` | **`MASKED` 불가** |

개인 식별을 막으려고 단독주택·토지·상업용은 지번 뒷자리를 가린다.
**설계로 못 푸는 한계**이며, 법정동 단위 집계까지만 쓸 수 있다.

> 화면에서 단독주택 단지에 "실거래 없음" 이 보이면, 거래가 없는 게 아니라
> **매칭이 불가능한 것**이다. 이 구분을 UI 에 드러낼지는 미정.

## 5. 단지 설계

**단지코드**: `INT IDENTITY(1,1)` — 1, 2, 3 …

**묶는 규칙**:
```
root_bldrgst_pk = mgmUpBldrgstPk 가 '0'/NULL 이 아니면 그 값, 아니면 자기 자신
전유부(regstrKindCd=4)는 호 단위이므로 제외
```

**재현 가능성**: `gold.complex_identity` 에 식별 근거(`ROOT_PK`)를 남긴다.
재적재 시 identity 로 기존 단지를 다시 찾으므로 코드가 재현된다.
이 장치가 없으면 적재할 때마다 새 코드가 발급되어 단지코드가 무용지물이 된다.

**PNU 는 단지 묶기에 쓰지 않는다.** 지번은 분할·합병으로 바뀐다. 토지 연계에만 쓴다.

**단지명은 세 단계로 찾는다** (`14_complex_nm.sql`):

```
총괄표제부(1)  >  집합건축물 표제부(3)  >  일반건축물(2)
없으면 대표 주소로 대체하고 complex_nm_src = 'ADDR' 로 남긴다
```

출처를 `complex_nm_src` 에 기록하는 이유: 없으면 주소인지 진짜 이름인지 구분할 수
없어, 한 번 주소가 들어간 단지를 영영 못 고친다. 전유부(`4`)는 쓰지 않는다 —
`root_bldrgst_pk` 가 표제부를 가리켜 다단계 단지에서 어긋난다. 상세는 `정책.md` 2장.

### 전체 (시군구 하나를 끝까지)

```powershell
cd C:\Project\Teomoony\etl

순서가 강제된다:
```

2 bld        건축물대장 4종       <- 기본개요가 먼저여야 단지가 묶인다
3 build      단지 구성           <- 실패하면 중단 (뒤 단계가 옛 단지로 돌면 조용히 틀린다)

이미 적재된 법정동은 건너뛴다. 중간에 끊겨도 다시 돌리면 이어서 간다.

## 8. 환경 함정

- **`user: "0:0"`** — SQL Server 2022 컨테이너는 비root 로 돈다. named volume 이
  root 소유라 이게 없으면 `Access is denied` 로 기동 실패.
- **`sqlcmd -I`** — `QUOTED_IDENTIFIER` 기본 OFF. 없으면 PERSISTED computed column
  과 filtered index 테이블 생성이 실패한다.
- **`.cmd` 는 ASCII 만** — `cmd.exe` 가 배치 파일을 CP949 로 읽어 한글 주석이
  줄 파싱을 깨뜨린다.
- **PowerShell** — `npm` 은 `.ps1` 이라 실행 정책에 막힌다. `npm.cmd` 를 쓴다.
  현재 창 PATH 가 안 잡히면 `$env:Path = "$env:ProgramFiles\nodejs;$env:Path"`.
- **건축물대장 API 는 페이지당 100건 상한** — `numOfRows=1000` 을 줘도 잘린다.
- **VWorld 는 법정동 단위 1회 호출** — `attrFilter=pnu:like:<법정동코드>`,
  `crs=EPSG:4326` 으로 받으면 좌표 변환이 아예 필요 없다.

## 10. 작업 로그 — 잡은 버그

**① 단지코드 재사용** (합성 샘플)
`usp_resolve_complex` 가 OUTPUT 변수를 초기화하지 않았다. T-SQL 의
`SELECT @x = ...` 는 행이 없으면 변수를 **그대로 둔다**. 두 번째 호출부터
직전 단지코드를 들고 들어가 "이미 존재함" 으로 오판.
→ 프로시저 선두에 `SET @complex_id = NULL;`

**② `road_coverage` 가 정상을 실패로 오판** (합성 샘플)
분자를 `DISTINCT 건물관리번호` 로 셌는데 분모는 동 수. 여러 동이 같은
도로명주소를 공유하는 정상 케이스가 2/3 → 1/3 로 나왔다.

**③ `mgmUpBldrgstPk = '0'` 을 PK 로 오독** (실데이터)
`0` 은 "부모 없음" 센티넬인데 유효 PK 로 취급해 "부모가 다른 법정동에 있다" 고
잘못 결론 냈다.

**④ `key_cols` vs `keys` 불일치** (코드 리뷰)
검증된 매핑을 적재기에 이식하면서 키 이름이 어긋났다.

**⑤ 단지↔필지 PK 위반** (범위 확대)
한 PNU 가 어떤 동의 **대지**이면서 동시에 다른 동의 **부속지번**일 수 있다.
`SELECT DISTINCT complex_id, pnu, pnu_role` 이 역할별로 두 행을 남겨
PK(complex_id, pnu) 에 같은 키를 두 번 넣으려다 터졌다.
청운동 1개 법정동에는 그런 필지가 없어 안 드러났다.
→ `(complex_id, pnu)` 로 묶고 `MAX(pnu_role)` (MAIN 우선).

**⑥ 단지 구성 실패를 무시하고 진행** (⑤의 2차 피해)
`load_sgg.py` 가 3단계 실패를 무시하고 4~6단계를 돌려서, **옛 단지 321개**
기준으로 조용히 틀린 결과를 냈다. 기본개요는 94,718건 들어왔는데 단지가
321개인 게 유일한 단서였다.
→ 단지 구성 실패 시 즉시 중단.

**⑦ 매칭 결과가 갱신되지 않음** (실거래가)
자연키가 같으면 INSERT 를 건너뛰는데, 해제 여부만 UPDATE 하고 매칭은 다시
계산하지 않았다. 첫 적재 때 법정동코드가 없어 `NO_LAWD` 로 남은 14,049건이
코드를 채운 뒤에도 그대로였다. **"행이 이미 있다"와 "매칭이 이미 끝났다"는
다른 얘기**인데 하나로 취급한 설계 실수.
→ 매 실행 끝에 재매칭 패스. 복구 14,049건, 매칭률 8.8% → 99.94%.

**⑧ `stcnsDelayDay` 를 일수로 읽음** (2026-10-16, 화면까지 나감)
이 필드는 **착공기한**(허가 + 2년, 연장 시 3년)이지 지연 일수가 아니다.
`fmt()` 가 콤마를 찍어 **`착공지연 20,170,910일`**(5만 5천 년)이 화면에 떴다.
해당 건(석계역 한일노벨리아시티)은 기한을 **45일 앞당겨 지킨** 건이다 — 정반대로 표시됐다.
발원지는 스키마다: `11_arch_permit.sql` 의 날짜 컬럼 6개 중 **이 하나만 주석이 비어 있었고**,
프론트가 이름으로 추측해 그 빈칸을 메웠다.
→ 착공기한은 날짜로 표기. 지연은 `착공예정 vs 실제착공` 으로 계산(커버리지 42건 → 737건).
**주석을 채웠다.**

**⑨ 집계 안의 스칼라 서브쿼리 — 관리비가 한 번도 동작한 적 없었다** (2026-10-16)
`SUM(CASE WHEN x < (SELECT ...))` 를 T-SQL 이 거부한다. `/api/complexes/:id` 가 통째로
500 이라, **K-apt 연결이 있는 51개 단지는 상세 화면 자체가 안 열렸다**(실거래·동·필지까지).
연결이 없는 54,013개는 `costOf` 가 먼저 null 로 빠져나가 멀쩡해 보였다.
→ 비교값을 CTE 로 올려 해결.
**교훈: "에러가 안 보인다" 는 "에러가 없다" 가 아니다.** 그 경로를 아무도 안 밟았을 뿐이다.

**⑩ 총괄표제부를 안 보고 동별만 봄 — 주차 1,177대가 화면에서 사라짐** (2026-10-16)
제원 쿼리가 주차·주용도·에너지·녹색건축·지능형 **9개 항목**을 '총괄에 없는 항목'으로
분류해 동별 표제부에서만 구했다. 총괄에는 다 있다. **아파트는 주차장이 단지 전체
단위라 총괄에 적히고 동별은 0** 이라, 24개동 단지에서 합이 0 이 되고 줄이 사라졌다.
API·ETL·테이블 세 겹이 다 멀쩡했고 **마지막 쿼리 한 겹에서만 끊겼다.**
→ 총괄 우선 / 동별 폴백. 총계 vs 내역 합 7대 차이는 화면이 적는다.
(컬럼은 `02_silver.sql` 이 아니라 `05_revise.sql` 이 ALTER 로 추가한다 — 한쪽만 보면 틀린다)

> ①②④⑥⑦ 은 **조용히 틀린 결과**를 냈을 종류다. 터지는 것보다 위험하다.

### 미결 — 등기

4축 중 유일한 공백이다. 공공데이터포털에 등기부등본 오픈 API 가 **없고**,
등기는 부동산고유번호(14)를 써서 PNU(19)와 체계가 다르다. 주소 문자열 정규화
매칭밖에 없다. 결정이 필요하다: 실거래가로 대체 / 유료 데이터 도입 / 계속 보류.

### 미결 — 전국 확대

종로구 하나가 40분 걸렸다. 전국 250여 시군구면 API 건별 호출로는 비현실적이다.
**EAIS 월배치 파일**로 가야 하고, 그러면 적재 파이프라인이 통째로 달라진다
(파일 파싱 + BULK INSERT). **스키마와 단지 묶기 로직은 살아남는다.**
자세한 영향은 `정책.md` 9장.

### 미결 — 현행화

건축물대장은 변동분 API 가 없다. 하이브리드가 정석: 대량은 EAIS 월배치, 단건은 API.
`meta.ingest_run` 과 `gold.v_staleness` 가 판단 근거를 쌓는다.

### 선택 — 도로명 원본

건물관리번호를 VWorld 가 주므로 급하지 않다. 남은 건 우편번호와 주소 변동이력.

### 선택 — 성능

- 검색이 `LIKE '%...%'` 라 인덱스를 못 탄다. 전국 규모면 전문검색 필요
- `gold.v_lawd_map` 이 검색어마다 단지·거래를 다시 센다. 요약 사전 계산 필요
- 시군구코드 기준 파티셔닝 (현재는 filtered index 만)
- `sa` 계정 평문 비밀번호 — 개발 단계라 유보 중
